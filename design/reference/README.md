# 页面视觉稿参考

这三张 PNG 是用户提供的页面视觉稿的正式副本。前端页面设计与实现以其**内容区域的布局、层级、配色和组件样式**为参考；手机外框、系统状态栏、示例姓名、日期、余额和餐费只用于展示，不进入产品页面或固定数据。

| 文件 | 对应页面 | 应保留的视觉关系 |
| --- | --- | --- |
| `login.png` | 员工登录 | 食堂照片与品牌标识构成顶部场景；手机插画辅助说明；白色圆角登录表单突出手机号、密码和蓝绿渐变主按钮；底部波浪收尾。 |
| `employee-home.png` | 员工首页 | 食堂场景页头、问候与头像；余额为首要信息；就餐码入口紧随其后；常用入口、餐次卡片、最近资金流水和四项底部导航依次排列。 |
| `terminal-verify.png` | 核销终端 | 顶部终端与窗口状态、显著结果区、员工必要身份提示、消费信息、重复消费确认、近期扫码事件和等待扫码区域形成清晰层级。 |

## 按已确认业务规则调整

- 首页视觉稿里的“去充值”改为线下充值说明入口，保留余额卡片的视觉层级；不出现不可用的在线充值操作。
- 核销视觉稿里的账户余额从公共终端移除。结果区只展示状态、金额、餐次、时间和必要身份提示；余额在员工本人 H5 中查看。照片可选，不能作为身份核验依据。
- 核销视觉稿把成功、再次消费提醒和等待扫码放在一张展示图中。实际产品按状态分别呈现，同餐次提醒只在新 Token 再次消费时出现。
- 核销终端由 USB 扫码枪读取；画面中的扫码框是等待状态装饰，不表示相机扫描。终端布局按实际屏幕宽度重排，不套用手机窄屏比例。
- 登录后的首次修改临时密码、Token 过期、扫码失败、余额不足、设备离线等状态按同一视觉语言补齐。

验收时并排审阅页面稿与参考图，检查主要区块顺序、留白、圆角卡片、蓝绿渐变、深蓝文字、状态色及素材使用。响应式布局和上述业务规则允许有明确说明的调整；示例数值和手机外框不作为像素级复刻目标。
