# 扫码去重与员工确认同餐次再次消费

- 状态：Accepted
- 日期：2026-09-26

首次有效码且可确定餐次的扫码，在服务端接收时启动固定 3 秒去重窗口。去重键为员工、业务日期和餐次，跨就餐码及终端生效；成功、待确认和业务失败均可启动窗口，重复扫码不延长窗口。并发扫码必须在服务端原子地归并到同一结果，不能多扣款。重复触发返回首次扫码结果并带重复标记，终端不再次按新消费播报或打印；每次重复触发保留独立扫码事件并关联首次结果，不产生第二笔消费或资金流水。同一码成功后重放始终返回首次结果；超过 3 秒且使用新码时，若该餐次没有未退款消费则可正常消费，否则创建待确认消费。同一员工、业务日期和餐次最多有一笔待确认消费。

待确认消费由就餐码所属员工在原有效登录会话中确认，服务端核对归属，重复确认返回同一结果；终端没有确认扣款权限。确认页展示扫码时服务端记录的餐次和金额，实际扣款使用相同快照。扫码时一并保存原餐次结束时间；管理员随后修改餐次配置，不改变这笔请求的确认期限。待确认请求在扫码后 60 秒或所保存的原餐次结束时刻中较早者失效，二维码轮换或过期本身不撤销已发起的待确认请求；确认时仍需检查会话、账户和余额。员工取消、超时或餐次结束均不扣款，并形成可供终端恢复查询的最终状态。取消或失败后若要重试，员工需出示新码。

首次扫码的餐次按服务端接收扫码时的业务日期和当前餐次判定；若无当前餐次则失败。已全额退款的消费不计入同餐次再次消费判断。本决策取代 [ADR-0001](0001-mvp-architecture-and-money-model.md) 中“同餐次再次消费在终端逐笔确认”的规定；确认权交给员工本人，以免工作人员替员工授权再次扣款。
