# 就餐码出示与消费结果同步

- 状态：Accepted
- 日期：2026-09-26

员工就餐码按约 30 秒轮换，单码有效期约 60 秒；轮换期间旧码仍可能被扫码。一次出示流程可以跨页面离开和返回，直至消费有结果后由员工主动开始下一次。浏览器在当前登录会话中保留仍有效的码、`expiresAt` 和出示流程状态，多个标签页共享；返回时立即展示有效缓存码，同时向服务端校正。码是否可用最终由服务端时间及状态决定，手机断网时只展示尚未过期的缓存码。

服务端提供员工鉴权的出示流程状态接口，覆盖本次出示期间签发的所有码，包括已轮换的旧码，并返回待确认、失败或成功的权威结果。员工页在前台短轮询，切后台时暂停，恢复时立即查询；各码到期且服务端确认没有待处理结果后停止跟踪该码。成功或明确失败后停止等待对应码，成功页保留该笔详情，直至员工主动再次出示。终端对待确认消费短轮询最终状态，断线后按原待确认编号恢复结果。

成功详情使用消费对应的资金流水 ID 生成消费编号，并使用消费发生时的金额、餐次编码和名称快照以及实际扣款时间。系统不引入独立订单实体。状态接口避免让页面用余额或流水变化推断扫码结果，也避免把原始就餐码作为状态查询参数。
