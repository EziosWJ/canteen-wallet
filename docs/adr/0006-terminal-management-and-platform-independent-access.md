# 后台管理扫码终端与跨平台接入

为简化扫码点位管理与部署，扫码终端及其独立凭据由管理后台创建和管理，支持再次查看、复制、重置 key 和启停终端；重置后旧 key 立即失效。跨平台接入以公开文档描述的终端 API 为契约，电脑客户端与 ESP32 等嵌入式客户端均可调用，服务端与扫码代理支持分机部署。

本决策更新 [ADR-0001](./0001-mvp-architecture-and-money-model.md) 中现场 Linux 主机同时承载服务端与扫码代理的部署假设。为允许重装终端时直接取回原 key，凭据需要可恢复存储，不能继续仅保存哈希。这一变化仅涉及终端凭据，就餐码的哈希存储规则仍适用。

终端使用一个服务端地址接入，支持 HTTP 和 HTTPS；终端 API 应能通过该地址访问，不要求客户端另外配置内部 API 与 Web 地址。本次官方客户端交付范围为 Linux Agent，同时提供通用 HTTP 接入文档、调用示例及 ESP32 调用示例；Windows、macOS 等客户端可按相同协议接入。部署由项目实施者完成，使用环境变量启动并提供最简文档；暂不制作安装包、安装脚本或设备自动选择流程。

官方 Linux Agent 保留扫码、启动及定期心跳、待确认消费查询和结果反馈的完整流程。自制客户端只需实现扫码请求，心跳和待确认结果查询作为可选能力；文档同时提供最小扫码示例与完整流程示例。未发送心跳的终端显示“未报告心跳”，不能仅据此判定扫码不可用；未查询后续结果的客户端收到待确认响应时，应提示员工在手机确认，不能展示为消费成功。

后台创建终端时只填写名称，系统自动生成编号与 key；提供改名、查看或复制 key、下载配置、重置 key 和启用或停用操作。key 默认遮盖，由管理员主动查看或复制；退役终端通过停用处理，保留历史引用。

终端 key 直接存入数据库，仅允许已登录管理员查看，日志和审计记录不记录 key 内容。选择直接存储是为了减少服务器密钥管理和部署步骤；数据库及备份因此包含可直接使用的终端凭据。既有仅保存哈希的 key 无法还原，升级后可继续鉴权，但重新取得原 key 需使用原凭据文件或执行重置。

Linux Agent 的目标配置是服务端地址、终端 key 和扫码设备，通过环境变量启动，保留现有设备模式与本地显示配置能力；支持直接通过环境变量提供 key，原凭据文件方式可兼容保留。统一地址与直接 key 分别使用 `CANTEEN_SERVER_URL` 和 `CANTEEN_TERMINAL_KEY`，优先于对应旧配置；新变量非法时明确报错。原双地址与凭据文件方式保留兼容。

用户已确认完整方案，并通过 SPEC-007（GitHub #56）授权实施。启动方式见 [最简部署文档](../../deploy/scan-agent.md)。
