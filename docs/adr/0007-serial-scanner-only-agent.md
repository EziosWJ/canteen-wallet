# 扫码代理改用串口扫码枪

- 状态：Accepted
- 日期：2026-10-12
- 取代：[ADR-0006](./0006-terminal-management-and-platform-independent-access.md) 中“保留现有设备模式与本地显示配置能力”一项

本 ADR 记录扫码代理的扫码枪接口由“输入设备或 HID 设备”改为“串口设备”的决定。ADR-0006 的其余内容继续有效；其中“保留现有设备模式”改为下文所述的单一串口设备模式。

## 背景

现场扫码枪同时存在 RS232、USB 转串口和 TTL 三种接口形态，约定参数为 115200、8 位数据、无校验、1 位停止位（8N1）。现有代理把扫码枪当作键盘类设备读取，只实现了两种模式：`evdev` 读 `/dev/input/eventX`，`hidraw` 读 `/dev/hidrawX`，两者都以键盘 Enter 键作为一帧结束。这两种模式都读不到串口接口的扫码枪，波特率、数据位和后缀配置在代码里也无从表达。

`evdev` 分支还写死了 Linux amd64 的 24 字节 `input_event` 布局，使设备读取与 CPU 架构绑定；而串口按字节流读取，与架构和操作系统无关。

最初的系统设计本来就是串口优先：早期任务的设备抽象为 `Scanner ├── SerialScanner └── HIDScanner`，并写明“优先完成虚拟串口适配”。本次不是改变意图，而是回到原设计。

移除两种既有模式在本次是安全的：现网没有已装机的扫码终端（开发库中终端记录为零；快照库中唯一的终端从未发送过心跳，其扫码事件全部来自引入代理当天的开发自测）。因此本次不保留兼容层，也不保留无人使用的代码分支。

代价是失去键盘类扫码枪的读取能力。ADR-0006 未承诺设备模式长期不变，而现场约定的三种接口都可用串口读到；若将来需要键盘类扫码枪，应作为新的设备模式重新决策，而不是恢复本次删除的代码。

## 决定

### 1. 只保留串口设备模式

代理只通过串口读取扫码枪。删除 `evdev` 与 `hidraw` 两条读取路径及其专用的键码映射、`input_event` 解析和 HID 报文解析代码，不保留任何兼容分支。

`CANTEEN_SCANNER_MODE` 随之移除。该变量被设置时启动直接报错并说明已移除，而不是静默忽略——旧配置文件或旧文档带来的配置应以一句明确提示结束，而不是表现为一个难以理解的设备路径错误。

设备路径仍由 `CANTEEN_SCANNER_DEVICE` 配置，语义变为串口设备路径。不因本次变更改名：语义未变，改名只会带来配置、文档与后台下载模板的额外改动。推荐使用 `/dev/serial/by-id/` 下的稳定路径，避免插拔顺序导致 `/dev/ttyUSB0` 与 `/dev/ttyUSB1` 互换。路径必须显式配置，不自动选择端口——多适配器时自动挑选会读到错误的设备。

### 2. 串口实现使用 go.bug.st/serial

选用 `go.bug.st/serial`（v1.8.0）。它是纯 Go 实现，Linux 路径不需要 cgo，`GO_ENABLED=0` 可静态构建；唯一的间接依赖 `golang.org/x/sys` 已在仓库中，且引入后版本不变。

它承担了手写实现最容易出错、又最难自查的一类细节：`O_NOCTTY` 打开、`CLOCAL` 与 `CREAD`、关闭 `ICRNL`/`ISIG`/`OPOST`/`IXON`/`IXOFF`/`CRTSCTS` 的原始模式、以 `CBAUD` 掩码加 `Ispeed`/`Ospeed` 设置波特率、`VMIN`/`VTIME`，以及 `TIOCEXCL` 独占访问。其中 `SetReadTimeout` 直接提供了下文空闲帧判定所需的原语：超时读取返回零字节且不报错。

不选 `github.com/tarm/serial`：2018 年后无维护，且没有读超时接口（只能在打开端口时按 `VTIME` 定为 0.1 秒粒度），无法实现空闲帧判定。手写实现（`golang.org/x/sys/unix`）实测可行且零新增依赖，本次不采用，因为收益只是省下一个已在仓库的间接依赖，代价是自行承担上述全部 termios 细节、读取取消与错误重试。

### 3. 配置面

在现有 `CANTEEN_SCANNER_*` 命名下新增三项，取值一律白名单校验，非法值在启动时报错而不是退回默认值：

- `CANTEEN_SCANNER_BAUD`，默认 `115200`，允许 `9600`、`19200`、`38400`、`57600`、`115200`、`230400`。
- `CANTEEN_SCANNER_TERMINATOR`，默认 `any`，允许 `any`、`cr`、`lf`、`none`；`any` 表示 CR 与 LF 任一都算一帧结束，`none` 表示只靠空闲判定。
- `CANTEEN_SCANNER_IDLE_MS`，默认 `50`，允许 `10` 至 `500`。

数据位、校验位和停止位本次固定为 8N1，不做配置。三种接口形态都支持 8N1，为 7E1 增加配置面与测试面没有依据；真遇到这类扫码枪时再作为一项单独变更追加。

参数配错在串口上表现为静默乱码而不是错误，因此校验必须发生在启动时：非法波特率、非法终止符、越界空闲阈值都直接退出。这一选择与 ADR-0006 已确立的“新变量非法时明确报错”一致。

### 4. 帧界判定

串口只有字节流，没有键码，一帧的结束由扫码枪配置的后缀决定。判定顺序固定为：先按终止符切分；终止符之外，读取在 `CANTEEN_SCANNER_IDLE_MS` 内没有新字节即认为当前帧结束。

顺序不能颠倒的两步：先剥掉帧首尾的 NUL、CR、LF、空格和 TAB，再检查剩余部分是否含不可打印字节。含不可打印字节的帧整帧丢弃并记 WARN 日志；剥完为空的帧静默丢弃。若先按“含不可打印字节即丢弃”处理，被配置为定长补位（短码用 NUL 补齐）的扫码枪会一帧都读不出来，而症状是静默无反应，最难排查；先剥首尾再查中段同时容纳定长补位，并仍然吃掉波特率错配产生的中段乱码。

帧长上限 128 字节，与服务端对就餐码的拒绝阈值一致；超限的帧整帧丢弃并重置缓冲，不截断提交——截断会产生一个看起来合理但错误的值。

剥完后不为空即提交服务端，不在客户端校验就餐码前缀或格式：格式契约属于服务端，复制到客户端会在契约变化时静默失效；非法内容由服务端返回“无效就餐码”。

### 5. 日志与状态

波特率错配的现象是“扫码枪显示在线、扫码没有反应、服务端回报无效就餐码”，是本次变更最难自查的故障。丢弃帧时记 WARN，带字节数与一次性提示（检查波特率与扫码枪后缀配置）。

重连节奏沿用现状（打开失败 2 秒、读取失败 1 秒）；同一路径连续失败只在首次记 WARN，其后降为 DEBUG，状态发生变化时重新记 WARN。

本次不为乱码计数增加界面展示：终端页由服务端打包的资源提供，增加该能力会引入前端与前后端字段改动，超出“只替换设备输入层”的范围，记为后续可选项。

### 6. 改动边界

扫码设备读取之外的代理能力（心跳、待确认消费查询、重启恢复、结果展示、离线语义、可选语音）一行不改，其行为由 ADR-0002 与 ADR-0003 约束且已有人工验收记录。

终端 API 契约不变，`docs/terminal-api.md` 与 ESP32 示例不受影响。`CONTEXT.md` 不新增术语：“扫码枪”指物理读取设备、“扫码终端”指已登记点位，两者已定义清楚，“扫码枪使用串口”是实现约束而非领域概念，属于部署文档。

随本次一并更正的既有失真内容：后台下载的终端配置模板、systemd 单元的补充组（`input` 改为 `dialout`）与单元描述、仓库首页说明和终端页上“由 USB 扫码枪读取”的文案、以及部署文档中的模式表。

### 7. 验收边界

串口设备层此前没有任何自动化测试（键码映射与两种读取循环均无测试，也没有任何测试运行过代理二进制）。本次为帧化逻辑补单元测试，为设备层补基于 PTY（伪终端）的集成测试，覆盖打开、读取、超时、关闭与重新连接。

自动化测试只覆盖帧化与设备层行为。真实扫码枪、两端参数一致性和后缀配置属于现场人工验收，不以无硬件的测试声称设备已兼容——这一边界沿用 SPEC-007 已确立的做法，现场演练由现场验收票承载。

注意 `TIOCEXCL` 独占访问的运维含义：端口被其他进程占用（例如 `ttyUSB0` 上挂了 `serial-getty`）时打开会失败，文档需写明这一现象。

## 后果

- 代理不再依赖键盘类扫码枪，设备读取与 CPU 架构解耦；`//go:build linux` 仍保留，本次不交付 Windows 或 macOS 客户端。
- 现场配置比 ADR-0006 描述的多三项（波特率、终止符、空闲阈值），且与前两种模式相比多了一份“扫码枪必须配置为 115200 8N1 并带后缀”的两端契约。这份契约最容易出错，必须写进部署文档。
- 扫码枪在位但断电时，串口不报错也不产生数据，`scanner_status` 会一直显示在线。这与移除前的行为一致（断电的输入设备同样不产生事件），本次不增加健康检测，仅在文档中写明。
- 移除两种模式后，键盘类扫码枪不再可用。若现场换用这类扫码枪，需要作为新的设备模式重新决策。
- 设备层首次有测试覆盖；`cmd/scan-agent` 的配置测试需把设备路径占位从 `/dev/input/event-test` 改为串口路径，后台配置下载的验收测试需补断言。
- 后台下载的终端配置不再包含设备模式，设备路径占位改为串口路径；已下载的旧配置文件在新代理上会因模式变量报错而显式失败，不会静默按错误方式读取。
